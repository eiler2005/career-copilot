# От установки до проверяемого рабочего цикла

[English](../GETTING_STARTED.md) · [Русский](GETTING_STARTED.md) · [Документация](../../README.ru.md#документация)

Офлайн-пример использует вымышленные данные и не вызывает модельный API. Он показывает импорт доказательств, оба CV-трека, запись исследования компании, планы, версии пакетов, replay, статистику и проверенное восстановление. Документы намеренно остаются в ожидании ревью.

## Установка

Нужны macOS/Linux, Python 3.12+, [uv](https://docs.astral.sh/uv/getting-started/installation/) и Unicode TTF. На Linux обычно подходит DejaVu Sans, на macOS — Arial. При проблемах задайте установленный шрифт в приватном `settings.json` → `pdf_font`.

```sh
git clone https://github.com/eiler2005/career-copilot.git
cd career-copilot
uv sync --all-groups
uv run ajh --help
```

Название проекта — Career Copilot; `job-search-agent`, `job_search_agent` и `ajh` сохранены как имена дистрибутива, модуля и CLI для совместимости.

## Полный офлайн-пример

Выберите **новый несуществующий** абсолютный путь. Соседние пути с окончаниями `-backup` и `-restored` тоже должны быть свободны.

```sh
uv run python scripts/demo_workflow.py --home /tmp/career-copilot-demo-EXAMPLE
uv run ajh --home /tmp/career-copilot-demo-EXAMPLE report --open
uv run ajh --home /tmp/career-copilot-demo-EXAMPLE stats
uv run ajh --home /tmp/career-copilot-demo-EXAMPLE verify
```

Скрипт создаёт вымышленные факты, импортирует существующий синтетический файл доказательств, фиксирует задания агентам, оценивает оба трека, собирает два мастера и пакет вакансии, создаёт учебную работу и дважды разбирает сохранённый ответ Greenhouse. Он проверяет повтор finish и совпадение backup/restore. Сетевой поиск, отправка и модельное авторство не имитируются.

| Результат | Что проверить |
| --- | --- |
| `report/index.html` | Компании, вакансии, документы, ревью, обучение, события |
| `demo-results.json` | Реальные ссылки на результаты этого запуска и проверки |
| `packages/` | Исходник, PDF, текст, покрытие, контекст, задание |
| `activities/` | Завершённая механическая работа и честная блокировка требуемой модели |
| Соседние `-backup`, `-restored` | Копия с manifest и восстановленное пространство |

Успешная проверка целостности при ожидающих ревью — нормальный результат. Пример не приписывает механический CV флагману и не заявляет, что рецензент осмотрел документ. Откройте PDF для знакомства с рендерером; реальное содержательное и визуальное ревью выполняется отдельно агентом.

Для нового запуска нужен другой путь: скрипт не перезаписывает прежнее пространство или backup. Временная папка подходит демонстрации, но не реальным карьерным материалам.

## Собственное приватное пространство

Выберите постоянную папку вне публичного checkout:

```sh
uv run ajh --home /absolute/private/career-workspace init
```

Подготовьте приватный JSON фактов с данными кандидата, ссылками на доказательства и ровно двумя профилями: `product`, `technical-leadership`. Формат — в [модели данных](DATA_MODEL.md#факты-кандидата). Каждый источник, который не URL, должен быть существующим файлом относительно импортируемого JSON.

```sh
uv run ajh --home /absolute/private/career-workspace facts import /absolute/private/import/facts.json
uv run ajh --home /absolute/private/career-workspace record companies /absolute/private/import/company.json
uv run ajh --home /absolute/private/career-workspace record vacancies /absolute/private/import/vacancy.json
```

Карточки заменяются целиком. Сохраняйте остальные поля при обновлении, задайте трек и требования со ссылками перед оценкой. Источники и уровни настраиваются приватно по [справочнику](CONFIGURATION.md); публичный пример источника отключён до адаптации.

## Работа в Codex или Claude

Откройте checkout в существующей агентской среде. Репозиторные навыки обычно обнаруживаются автоматически; проект не устанавливает их глобально и не добавляет API-ключ. Claude-адаптеры ссылаются на канонические английские инструкции; результат готовится на нужном пользователю языке.

Примеры самостоятельных запросов:

- «Исследуй продукты, рынки и найм компании; неизвестный размер так и обозначь».
- «Адаптируй продуктовый CV к вакансии и объясни судьбу всех существенных фактов».
- «Сделай вступление естественнее, не меняя утверждений».
- «Интервью в следующий четверг. Расставь приоритеты пробелов и потренируй реальный кейс».
- «Какие документы ждут ревью, а какие отклики действительно отправлены?»

Координатор объединяет этапы по запросу. Каждый навык фиксирует start/finish с фактическим исполнителем и хешами входов/выходов. Внешние тексты и сложные суждения требуют Astra в Codex или Opus в Claude; отсутствие нужной модели даёт blocked. Подробности — в [контрактах](AGENT_WORKFLOWS.md).

## Завершить пакет и сохранить работу

Получите prepare-task, передайте реальный авторский исходник флагмана и покрытие, затем выполните независимое ревью точной версии в отдельной сессии флагмана. Визуально проверяются все страницы и извлечённый текст. [CLI](CLI.md) описывает авторов/редакторов и связь письма с CV, [эксплуатация](OPERATIONS.md) — поля ревью.

После работы обновите отчёт, посмотрите статистику, проверьте целостность и создайте backup. Проверьте восстановление. Готовность документов не означает отправку: реальные исходы записываются только по доказательствам и подтверждению пользователя.

Перед публичными изменениями прочитайте [приватность](PRIVACY.md) и [участие в разработке](../../CONTRIBUTING.ru.md). Реальные данные не входят в код, скриншоты, тесты, логи и историю Git.
