# Участие в разработке Career Copilot

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md) · [О проекте](README.ru.md)

Изменение должно улучшать конкретную часть работы: охват источников, доказательства, версии, документы или восстановление приватного состояния. Начните с [AGENTS.md](AGENTS.md), [рабочего цикла](docs/ru/WORKFLOW.md) и [приватности](docs/ru/PRIVACY.md).

## Среда разработки

Нужны macOS/Linux, Python 3.12+ и uv. Установите зависимости через `uv sync --all-groups`. CLI — `uv run ajh`; совместимые имена пакета/модуля не меняются.

Создайте синтетическое пространство вне checkout по [офлайн-руководству](docs/ru/GETTING_STARTED.md). В тестах и документации используйте вымышленных людей, компании и ответы источников. Не копируйте реальные профили, цели поиска, CV, снимки, словарь и приватные абсолютные пути в issue, patch или fixture, даже если отдельный факт публичен.

## Содержание изменения

Объясните наблюдаемую проблему и результат. В адаптере сохраняйте байты источника, стабильную идентичность, ограниченный доступ и различие пустого/частичного/ошибочного ответа. В миграции сохраняйте исходные ID/события/файлы, отвергайте неизвестные схемы и проверяйте восстановление. В документах сохраняйте доказательства, точные хеши и независимое ревью.

Редактируйте через `apply_patch`. Не включайте посторонние изменения, добавляйте в staging явные пути и не обходите privacy hooks. Полномочия ограничены запросом: изменение кода не разрешает отправку отклика, сообщения, релиз или push.

## Проверки

```sh
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run python scripts/check_docs.py
```

Для кода проверяйте полезное поведение: ошибка источника сохраняет наблюдения, replay идемпотентен, новый вход делает handoff устаревшим, рецензент независим от авторов/редакторов, телеметрия остаётся неизвестной, backup восстанавливается. Не пишите тесты, которые только ищут недавно добавленную формулировку.

Для сквозного изменения запустите `scripts/demo_workflow.py` с новым внешним каталогом и осмотрите реальные результаты. Не придумывайте положительное авторство или content/visual review ради зелёного примера.

Изменённые `SKILL.md` проверьте доступным валидатором skill-creator, а также по триггерам, границам, ссылкам и handoff. Канонические навыки остаются краткими, обычное обнаружение включено, Claude-адаптеры — обычные Markdown-файлы.

## Документация и графика

Основной язык README/docs — английский. Поддерживайте `README.ru.md`, `CONTRIBUTING.ru.md` и соответствующий раздел `docs/ru/` с сопоставимой практической глубиной. Сохраняйте старые канонические пути и переключатели языка.

Разделяйте реализованное поведение, необходимую работу человека/модели и ограничения. Примеры должны запускаться при заявленных условиях; локальный источник факта обязан быть существующим файлом. Для API используйте официальные ссылки и перепроверяйте их при изменении адаптера.

Графика находится в `docs/assets/`. Диаграммы с DOT-исходниками обновляются через `uv run python scripts/render_diagrams.py`; `--check` проверяет регенерацию и требует Graphviz. Осматривайте итоговые SVG; надписи должны читаться, обе версии — совпадать по смыслу, данные — оставаться синтетическими.

## Перед коммитом, push и релизом

Следуйте [проверкам публикации](docs/ru/PRIVACY.md): приватный словарь и Gitleaks, точные worktree/index/history, явный staging и содержимое релиза. Чистое дерево не очищает старые коммиты. CI не заменяет локальный приватный словарь.

Описание изменения должно сообщать конкретную проблему, новое поведение, выполненные проверки и существенные ограничения. Не заявляйте невыполненные тесты или ревью; не публикуйте приватную диагностику и найденные секретные значения.

Проект распространяется по [MIT](LICENSE). Сохраняйте совместимость добавлений с лицензией и необходимую атрибуцию.
