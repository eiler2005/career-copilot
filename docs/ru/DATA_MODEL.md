# Модель данных и версии

[English](../DATA_MODEL.md) · [Русский](DATA_MODEL.md) · [Документация](../../README.ru.md#документация)

SQLite хранит актуальные сущности и сохранённые решения, файлы — исходные доказательства и точные версии документов. Их связывают ID и хеши. Изменение текста HTML-отчёта не изменяет базу.

## Файлы пространства

| Путь | Назначение |
| --- | --- |
| `workspace.json` | Версия схемы и признак синтетического пространства |
| `settings.json` | Источники, политика, бюджеты и рендеринг |
| `facts.json` | Текущие факты кандидата и два профиля |
| `journal.sqlite` | JSON-записи, реестр артефактов, метаданные |
| `facts-history/`, `evidence/` | Сохранённые наборы фактов и локальные доказательства |
| `snapshots/` | Оригиналы ответов API и HTML |
| `packages/`, `reviews/` | Версии документов, задания, проверки |
| `activities/`, `activity-artifacts/` | Запросы/результаты навыков и копии входов/выходов с хешами |
| `learning/`, `report/` | Планы и формируемые локальные представления |
| `imports/`, `legacy/` | Оригинал миграции и старые файлы |

Всё это приватные данные. Внутренние пути артефактов относительны пространству; метаданные activity могут содержать абсолютный путь рабочего оригинала и не предназначены для публикации.

## Таблицы и сущности

`records(kind TEXT, id TEXT, payload TEXT)` имеет составной первичный ключ. `artifacts(path, sha256, bytes)` учитывает неизменяемые байты, `meta(key, value)` — метаданные runtime. Гибкость JSON не означает полную проверку схемы: используйте контракты CLI, проверяйте контролируемые операции Store и сохраняйте события.

| Вид записи | Связи и содержание |
| --- | --- |
| `companies` | ID компании, профиль бизнеса, доказательства размера, ссылки на досье |
| `vacancies` | ID компании/провайдера/объявления, URL, наблюдение, доступность, требования и допуски |
| `observations` | Неизменяемая связь вакансии, источника, снимка и нормализованных данных |
| `current_assessments` | Указатель актуальной оценки вакансии/трека; прежние оценки сохраняются |
| `assessments` | Вакансия + трек + хеш входов; доказательства требований и решение правил |
| `packages` | Мастер/вакансия + трек, текущая версия и история |
| `events` | Операция, ID сущностей, подробности и время |
| `source_health` | Попытка/успех, статус, HTTP, счётчики, следующая попытка |
| `activities`, `activity_events` | Работа hosted-навыка, исполнитель, результат и связи с событиями CLI |
| `company_dossiers`, `text_revisions`, `cover_letters` | Исследования и самостоятельные авторские материалы |
| `interview_plans`, `interview_practices`, `interview_feedback`, `interview_progress` | План → реальная практика → обратная связь → решение о прогрессе |
| `employer_responses` | Полученные ответы с доказательствами и ссылкой на зарегистрированную отправку |
| `submissions` | Подтверждённая пользователем отправка с точной версией |

## Факты кандидата

Минимальный вымышленный пример:

```json
{
  "schema_version": 1,
  "candidate": {"name": "Алексей Примеров", "contacts": ["alex@example.invalid"]},
  "facts": [{
    "id": "example-platform",
    "text": "Руководил вымышленным платформенным проектом.",
    "section": "experience",
    "verification": "self_reported",
    "claim_type": "historical",
    "sources": ["evidence-note.md"],
    "tracks": ["product", "technical-leadership"],
    "tags": ["platforms"],
    "substantive": true
  }],
  "profiles": {
    "product": {"headline": "Продуктовое руководство", "summary": "Синтетический пример.", "distinction_ids": []},
    "technical-leadership": {"headline": "Техническое руководство", "summary": "Синтетический пример.", "distinction_ids": []}
  }
}
```

До импорта создайте реальный `evidence-note.md` рядом с JSON. Строка, не являющаяся URL, считается путём и копируется в хранилище доказательств. Импорт проверяет уникальность ID, ровно два профиля, наличие источников и классификацию проверки, сохраняет `original_sources` и старый/новый набор фактов.

`verified` — зафиксированная оценка доказательств, а не автоматический эффект импорта. `self_reported` и `conflicting` остаются видимыми. `claim_type: target` не подтверждает достигнутый результат. Сохраняйте контекст работодателя/клиента/партнёра, официальную должность, период и личный вклад.

## Карточки компании и вакансии

Досье поддерживает `about`, `business_areas`, продукты, рынки, сегменты клиентов и сведения о найме со ссылками. Размер описывается через `metric`, `value`, `as_of`, `scope`, `source_url` и confidence/reliability. Отсутствующее число сотрудников нельзя заменить догадкой.

Вакансии нужны `id`, `company_id`, `title`, канонические `urls` и целевой трек/треки. Отдельно храните `role_family`, `role_type`, `level.raw`, `level.source`, `market`, `availability`, `status_checked_on`. Сбор не создаёт надёжной разметки уровня и семейства роли автоматически.

Требование содержит стабильный `id`, `text`, `source`, `mandatory`, необязательный `tag`, `evidence_fact_ids`, `evidence_reviewed`, `gap_type`. Поля `minimum_years`, `authorization`, `license` обозначают структурный пробел. `language_gate`, `eligibility_gate`, `role_family_gates[TRACK]` фиксируют самостоятельные pass/fail/неизвестно решения.

`record companies PATH` и `record vacancies PATH` **заменяют запись целиком**. Прочитайте текущую карточку и явно объедините изменения в приватном JSON. ID и одно новое поле не являются частичным обновлением и приведут к потере остальных полей.

## Оценки и документы

Хеш оценки включает вакансию, компанию, факты и политику. Решения правил: `priority`, `needs_clarification`, `not_suitable`, `watch`. Тег лишь предлагает факт; покрытие требует проверенной связи с подтверждённым фактом, который не является целью. Это консервативные правила, а не семантическая модель ранжирования.

Версия пакета сохраняет исходник, PDF, текст, письмо при наличии, контекст, покрытие, задание, автора, вклад редакторов, число страниц и хеши. Неизменённые входы используют прежнюю версию; новые создают новую. Ревью привязано к полному набору хешей и `version_id`.

Самостоятельное письмо связано с точным CV-пакетом, версией и хешем CV. Оно остаётся черновиком до включения в проверенный пакет. Запись редактирования связывает «до», «после» и пояснения; старый пакет не меняется.

Синтаксис — в [CLI](CLI.md), activity-контракты — в [работе агентов](AGENT_WORKFLOWS.md), проверка и миграция — в [эксплуатации](OPERATIONS.md).
