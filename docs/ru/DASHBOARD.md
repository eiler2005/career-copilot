# Приватный веб-интерфейс и размещение

[English](../DASHBOARD.md) · [Русский](DASHBOARD.md) · [Документация](../../README.ru.md#документация)

Веб-интерфейс читает существующий журнал SQLite. Компании, вакансии, версии документов, активности, подготовка, источники и история доступны через поиск, фильтры и подробные карточки. Можно переключаться между русским и английским. Файлы интерфейса входят в Python-пакет: отдельная JavaScript-сборка, внешний шрифт или CDN не нужны.

## Локальный запуск

Установите проект по [инструкции](GETTING_STARTED.md), затем укажите инициализированное внешнее пространство:

```sh
uv run ajh-dashboard --home /absolute/private/career-workspace --port 8100
```

Откройте `http://127.0.0.1:8100`. По умолчанию сервер слушает loopback; без `--port` используется 8080. Процесс работает в открытом терминале. `ajh report --open` по-прежнему создаёт отдельный локальный HTML-экспорт.

Сервер только читает данные. Исследование, обновление записей, подготовка и ревью документов проходят через `ajh` и [работу агентов](AGENT_WORKFLOWS.md). После локальных изменений обновите страницу. Копия на сервере обновляется отдельно и не синхронизирует изменения обратно в локальное пространство.

## Записи и география

В подробной карточке доступны поля, источники, связанные записи и сохранённые версии документов. Вложенные объекты и массивы раскрываются; доказательства не сводятся к краткому пересказу. Доступность вакансии, оценка, готовность документов и отправка остаются отдельными состояниями.

География вычисляется для отображения. Исходное описание местоположения сохраняется; страна, город и удалённый формат показаны отдельно. Явные структурированные поля имеют приоритет. Дополнительное распознавание ограничено поддержанными сочетаниями города со страной или штатом: произвольное слово перед страной не считается городом. Узкий контекст рынка также позволяет распознать известную российскую столицу, если в записи явно указан российский рынок. Неоднозначные города, несколько стран, широкие регионы и удалённый формат остаются неразрешёнными там, где источник не подтверждает ответ. Внешнего геокодирования и записи предположений в SQLite нет.

API использует `GET /api/workspace` для обзора и `GET /api/records/<kind>/<id>` для отдельной записи. В обзоре есть массивы `companies`, `vacancies`, `documents`, `activities`, `preparations`, `sources` и `history`; `legacy_files` сопоставляет старые ссылки с сохранёнными файлами. Исходный `payload` сохраняется, вычисленные поля находятся в `display`. Реестр скачивания содержит допустимые зарегистрированные артефакты с путями, размерами и хешами. `GET /api/artifacts/<path>` проверяет каталог, тип файла, путь и целостность. Разрешены корни `activities`, `activity-artifacts`, `evidence`, `learning`, `legacy`, `packages`, `reviews` и `snapshots`. Служебные файлы и настройки в корне пространства, исходные импорты, maintenance, символические ссылки и незарегистрированные файлы отклоняются, включая зарегистрированные пути вне разрешённых каталогов и типов. Это проверка пути, а не поиск паролей внутри содержимого документов. HTML и другие документы скачиваются вложениями и не исполняются внутри приложения.

## Docker и приватный доступ

В образ входят публичный код и файлы интерфейса. Зависимости экспортируются из `uv.lock` с `--frozen`; приложение устанавливается без дополнительного разрешения зависимостей. Приватное пространство подключается внешним томом только для чтения в `/data/workspace`. Процесс работает с UID/GID 10001; каталог и файлы должны быть доступны этой учётной записи для чтения. Allowlist контекста сборки включает только метаданные пакета и исходники, исключая сгенерированный байткод. Пароли, материалы кандидата и настройки конкретного хоста не должны попадать в контекст сборки и Git.

```sh
export AJH_WORKSPACE=/absolute/private/career-workspace
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8100/healthz
```

[Compose](../../compose.yaml) открывает порт 8100 только на loopback хоста. Заданы проверка здоровья, перезапуск, лимиты ресурсов и логов, файловая система контейнера только для чтения и ограниченные привилегии. Сохраните привязку к loopback: публикация порта без адреса открывает сервис за пределами хоста. Подробнее — [документация Docker](https://docs.docker.com/engine/network/port-publishing/).

Встроенной публичной системы входа нет. Для удалённого сервера используйте SSH-туннель:

```sh
ssh -N -L 18100:127.0.0.1:8100 YOUR_SSH_HOST_ALIAS
```

Откройте `http://127.0.0.1:18100` на своём компьютере. `YOUR_SSH_HOST_ALIAS` — приватно настроенное SSH-подключение. Публичный порт в firewall не требуется. Для HTTPS по домену нужна отдельная авторизация на шлюзе и TLS; одного изменения адреса прослушивания недостаточно.

## Копирование, обновление и восстановление

1. Приостановите запись в пространство и создайте [резервную копию приложения](OPERATIONS.md). Восстановите её в новый локальный каталог и выполните `ajh verify` для этой копии.
2. Подготовьте закрытый снимок SQLite для подключения только для чтения. Открытую WAL-базу нельзя безопасно переносить копированием одного `journal.sqlite`; используйте SQLite backup API. Для копии размещения без параллельной записи закройте соединения и переключите её в rollback journal mode перед переносом. Рабочую локальную базу не меняйте.
3. Передайте проверенное пространство по SSH в новый приватный каталог релиза. Ограничьте доступ и разрешите UID контейнера чтение. Сохраните прежнее пространство и образ до успешной проверки нового релиза.
4. Укажите новый снимок в `AJH_WORKSPACE` и пересоздайте контейнер. Проверьте здоровье, количество записей, скачивание документов и доступ через туннель. Обновление образа само по себе не обновляет данные.
5. Добавьте постоянные рабочие данные в шифрованный backup хоста и проверьте восстановление. Файловая система контейнера заменяема, внешнее пространство — нет. Успешная локальная копия приложения не подтверждает включение нового каталога в серверный backup.

Для отката выберите предыдущие образ и снимок данных, пересоздайте сервис и повторите проверки. При обновлении не удаляйте тома и не перезаписывайте сохранённые версии документов. Веб-интерфейс не меняет схему журнала и не требует повторного импорта старых данных.

## Проверки и ограничения

Перед публикацией кода или образа выполните проверки из [инструкции по приватности](PRIVACY.md). Тесты сервера проверяют HTTP, чтение SQLite, географию и границы доступа к артефактам. В браузере проверьте навигацию, поиск, фильтры, подробные карточки, скачивание и обе языковые версии на компьютере и телефоне.

`/healthz` проверяет готовность приложения, но не актуальность вакансий, положительное ревью или покрытие резервным копированием. Это приватный интерфейс только для чтения на стандартном HTTP-сервере Python, рассчитанный на loopback и туннель. Пользовательских аккаунтов, редактирования, автоматических откликов, фонового сбора и двусторонней синхронизации нет. Ошибки и журналы запросов не должны раскрывать записи кандидата или пароли.
